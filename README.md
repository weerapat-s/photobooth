# Photo Booth DSLR + iPad Web (กล้อง DSLR → Windows bridge → iPad → Nextcloud)

ระบบโฟโต้บูทแบบบริการตัวเองตามโครงสร้าง DSLR booth: กล้องติดเหนือจอและต่อ USB เข้ากล่อง Windows/mini PC ที่ซ่อนในบูท ส่วน iPad เปิดหน้าเว็บเป็นจอสัมผัสผ่าน Wi-Fi

**ใช้กล้องรุ่นไหนก็ได้ที่ digiCamControl รองรับ** (Canon/Nikon/Sony ฯลฯ) ระบบไม่ได้ผูกกับรุ่นใดรุ่นหนึ่ง — ขอแค่ digiCamControl มองเห็นกล้องและสั่งถ่ายได้ ตัวที่ทดสอบจริงบนเครื่องนี้คือ Canon EOS R

- **iPad (booth)** — เปิดหน้าเว็บ Photo Booth ลูกค้ากดเริ่ม ตรวจรูป และถ่ายใหม่เฉพาะช่องเอง
- **Windows bridge** — ควบคุมกล้องผ่าน digiCamControl และส่งสถานะ/ภาพกลับหน้าเว็บ
  จากนั้น backend จัดหน้าสตริป ทำวิดีโอ อัปโหลดขึ้น Nextcloud แล้วโชว์ QR
- **backend/bridge** — รันบน Windows ที่ต่อสาย USB กับกล้องโดยตรง; ไม่จำเป็นต้องมี Mac หรือแอป iPad แบบ native

ลูกค้ารับรูปและวิดีโอด้วยการสแกน QR ที่ชี้ไปยังลิงก์ Nextcloud เฉพาะของเซสชันตัวเอง

## แหล่งภาพ 5 โหมด (เลือก `digicam` สำหรับ DSLR booth)

| `CAPTURE_SOURCE` | ใครลั่นชัตเตอร์ | live view | ใช้เมื่อ |
|---|---|---|---|
| `digicam` (เลือกใช้) | ลูกค้ากดบนเว็บ iPad แล้ว Windows สั่งกล้อง | เฉพาะ DCC webserver | กล้อง DSLR ต่อ USB เข้ากล่อง Windows ที่ซ่อนในบูท |
| `folder` | เจ้าหน้าที่กดกล้อง / รีโมท | ไม่มี | ใช้ Capture One tether แล้วให้แอปวางภาพลงช่องว่าง |
| `mock` | เจ้าหน้าที่กดปุ่มถ่ายบนจอช่าง | ไม่มี | เทสต์ทั้ง pipeline โดยไม่ต้องมีกล้อง |
| `web` | ลูกค้ากดบน PWA | กล้องใน iPad | ทางเลือกสำรอง ไม่สามารถควบคุมกล้อง DSLR ผ่าน USB |
| `ipad` | แอป Native iPad สั่งกล้องผ่าน USB | อยู่ในแอป | ทางเลือกทดลอง ต้องมี CascableCore license และ Apple signing |

## ตั้งค่าแบบ DSLR booth + เว็บบน iPad

ตั้งค่า `.env` บน backend:

```env
HOST=0.0.0.0
CAPTURE_SOURCE=digicam
KIOSK_MODE=self_service
```

จากนั้น:

1. ต่อกล้องผ่านสาย USB data เข้ากล่อง Windows/mini PC แล้วเปิด digiCamControl ให้เห็นกล้อง
2. รัน backend บน Windows และให้ iPad ต่อ Wi-Fi วงเดียวกัน
3. เปิด `http://<IP-Windows>:4700` ด้วย Safari บน iPad
4. เพิ่มหน้าเว็บไว้บน Home Screen แล้วเปิด Guided Access ตามหัวข้อถัดไป เพื่อกันลูกค้าปัดออก

สายกล้องไม่ได้ต่อเข้า iPad โดยตรง เว็บเป็นรีโมต UI ส่วน Windows bridge เป็นผู้ควบคุม USB/PTP ของกล้อง จึงไม่ต้องใช้ CascableCore หรือ Apple Developer

เมื่อติดตั้ง shortcut ด้วย `npm run install-shortcuts` แล้ว Windows bridge จะเปิดเองหลังล็อกอินโดยไม่แสดงหน้าต่าง และจะเปิด digiCamControl ให้อัตโนมัติเมื่อหน้าเว็บตรวจกล้อง หน้า iPad ตรวจสถานะทุก 5 วินาที: ถ้าไม่พบกล้อง ปุ่มเริ่มจะถูกล็อก และจะปลดเองเมื่อกล้องพร้อม

ลิงก์ใช้งานจริงผ่าน HTTPS คือ **https://booth.ienas.site** เชื่อมด้วย Cloudflare Tunnel ชื่อ `photobooth-windows-local` และเปิดอัตโนมัติพร้อม Windows bridge โดยไม่ต้อง forward port เราเตอร์ หน้าเว็บโหมดบริการตัวเองต้องจับคู่ด้วย `WEB_PAIR_CODE` หนึ่งครั้งก่อนใช้งาน คุกกี้จับคู่เป็น HttpOnly/SameSite ส่วน `IPAD_API_TOKEN` แบบยาวยังเป็น master secret ของ API และ API แบบเดิมถูกปิดในโหมดนี้ไม่ให้คนภายนอกสั่งกล้องโดยไม่ยืนยัน

Scheduled Task **Photo Booth Bridge Watchdog** ตรวจทุก 1 นาที หาก backend หรือ Cloudflare Tunnel หยุดจะเปิดกลับอัตโนมัติ เพื่อลดโอกาสเกิด Cloudflare Error 1033 หลังโปรเซสถูกปิดหรือเครื่องกลับจาก sleep

### ล็อก iPad ไม่ให้ลูกค้าปัดออกจาก Photo Booth

เว็บไซต์บล็อกท่าทางระบบของ iPadOS เองไม่ได้ จึงใช้ **Guided Access** ของ iPad ซึ่งล็อกเครื่องให้อยู่ในเว็บแอปเดียวและต้องใช้รหัสเจ้าหน้าที่จึงจะออกได้:

1. iPad: **การตั้งค่า → การช่วยการเข้าถึง → การใช้งานเครื่องตามที่กำหนด (Guided Access)** แล้วเปิดใช้งาน
2. เข้า **การตั้งค่ารหัส → ตั้งรหัส Guided Access** และตั้งรหัสที่ลูกค้าไม่รู้ ปิด Touch ID สำหรับการออกถ้าไม่ต้องการให้ใครใช้นิ้วปลด
3. เปิด Photo Booth จากไอคอนบนหน้าจอโฮม ไม่ใช่แท็บ Safari
4. กดปุ่มด้านบนของ iPad 3 ครั้ง เลือก Guided Access แล้วกด **เริ่ม**
5. ทดสอบปัดขึ้น/สลับแอป: ต้องออกไม่ได้ หากเจ้าหน้าที่จะออก ให้กดปุ่มด้านบน 3 ครั้งและใส่รหัส Guided Access

อย่าปิดตัวเลือก **การสัมผัส** ในการตั้งค่าเซสชัน เพราะลูกค้ายังต้องกดปุ่มถ่ายบนจอ

## ตั้ง digiCamControl

1. ต่อกล้อง DSLR ผ่าน USB เปิดกล้อง ตั้งเป็นโหมด PC connection แล้วเปิด **digiCamControl** ให้เห็นกล้อง
2. **ปิด Capture One** ระหว่างใช้โหมด `digicam` — สองโปรแกรมจับกล้องพร้อมกันไม่ได้
3. ให้ digiCamControl เปิดค้างไว้ตลอดงาน (แอปคุยกับมัน ไม่ได้คุยกับกล้องตรง ๆ)

### live view ต้องใช้ webserver ของ digiCamControl

`UseWebserver` ถูกเปิดไว้ให้แล้วใน `C:\ProgramData\digiCamControl\settings.json` (สำรองไว้ที่ `settings.json.bak`)
แต่ digiCamControl bind พอร์ต 5513 ไม่ได้ถ้าไม่มีสิทธิ์ — log จะขึ้น `Unable to start webserver`

แก้ครั้งเดียวจบ เปิด **PowerShell แบบ Run as Administrator** แล้วรัน (ใส่ชื่อบัญชีเต็ม `คอม\ผู้ใช้` — `%USERNAME%` ไม่ขยายใน PowerShell จะได้ error 1332):

```bash
netsh http add urlacl url=http://+:5513/ user="เครื่องนี้\ชื่อผู้ใช้"
```

ตรวจว่าได้ผล: `netsh http show urlacl url=http://+:5513/` แล้วปิดเปิด digiCamControl ใหม่

(หรือจะเปิด digiCamControl แบบ Run as Administrator ทุกครั้งก็ได้ ไม่ต้องแก้ urlacl)

ถ้ายังเปิด webserver ไม่ได้ แอปจะ **ตกไปใช้ named pipe (`CameraControlRemoteCmd.exe`) ให้อัตโนมัติ** — ถ่ายได้ปกติ แค่ไม่มี live view บนจอลูกค้า

## เซสชันเริ่ม/จบยังไง

**โหมด `KIOSK_MODE=self_service`:** ลูกค้ากดเริ่มบน iPad → ระบบสั่งกล้องผ่าน Windows → ตรวจภาพแต่ละช่อง → ถ้าไม่ชอบกดถ่ายใหม่เฉพาะช่องนั้น รูปช่องอื่นไม่เลื่อน → เมื่อครบกดยืนยัน → จัดหน้า + ทำวิดีโอ + อัปโหลด + โชว์ QR

**โหมดเจ้าหน้าที่:** เจ้าหน้าที่กด "เริ่มเซสชันใหม่" บนจอช่าง → กดถ่ายทีละช่อง → ตรวจภาพแต่ละช่อง → ถ้าภาพเสียให้กด "ลบรูป" หรือ "ถ่ายใหม่" ที่ช่องนั้น รูปช่องอื่นจะไม่เลื่อน → เมื่อครบทุกช่องกด "ยืนยันรูปทั้งหมด + จบงาน"

**โหมด folder:** เจ้าหน้าที่กดเริ่มเซสชันก่อน แล้วกดชัตเตอร์เอง ไฟล์ JPEG จะลงช่องว่างถัดไป ต้องตรวจและกดยืนยันจบงานเองเหมือนกัน (ไฟล์ RAW ถูกข้าม)

## โครงสร้างไฟล์บน Nextcloud

```
photobooth/
  <booth>-<YYYYMMDD-HHmmss>/     # 1 เซสชัน = 1 โฟลเดอร์ (QR ชี้มาที่นี่)
    photo-1..N.jpg               # ไฟล์จากกล้อง
    card.jpg                     # การ์ด/สตริปที่จัดหน้าแล้ว (ไฟล์หลักที่ลูกค้าได้)
    video.mp4 / video.gif        # วิดีโอบูมเมอแรงจากช็อตที่ถ่าย
```

## ติดตั้ง

```bash
npm install
```

คัดลอก `.env.example` เป็น `.env` แล้วแก้ค่า (ไฟล์ `.env` ที่ให้มาตั้งไว้ตรงกับเครื่องนี้แล้ว)

## เปิดแบบแอพ (ไอคอนบนเดสก์ท็อป)

```bash
npm run install-shortcuts
```

ได้ไอคอน **Photo Booth** (จอลูกค้า เต็มจอ) กับ **จอช่าง** ทั้งบนเดสก์ท็อปและใน Start Menu

ดับเบิลคลิกแล้วจะเปิดเซิร์ฟเวอร์แบบซ่อนหน้าต่าง รอจนพร้อม แล้วเปิดหน้าจอในเบราว์เซอร์แบบ app window
ปิดหน้าต่างสุดท้ายที่ใช้พอร์ตนั้น = ปิดเซิร์ฟเวอร์ให้เอง (จอลูกค้ากับจอช่างใช้เซิร์ฟเวอร์ตัวเดียวกัน)

ออกจากโหมดเต็มจอ: `Alt+F4`
log อยู่ที่ `logs/booth.log` — ลบไอคอน: `npm run uninstall-shortcuts`

**จอลูกค้าอยู่คนละจอกับจอช่าง:** ตั้ง `BOOTH_MONITOR=2` แล้วเปิดไอคอน Photo Booth ระบบย้ายเต็มจอให้อัตโนมัติ

| `REVIEW_SECONDS` | 90 | โชว์ QR นานเท่าไหร่ |
| `EVENT_NAME` | | ข้อความบนสตริปและจอลูกค้า |
| `CARD_TEMPLATE` | | ไฟล์ PNG เทมเพลตการ์ด เว้นว่าง = วาดเลย์เอาต์เองตาม `PRINT_LAYOUT` |
| `CARD_TEMPLATE_HALF` | `left` | เทมเพลตที่วางสตริปคู่กัน ให้ตัดมาใช้ครึ่งไหน: `left`/`right`/`full` |
| `PRINT_LAYOUT` | `strip2x6` | `strip2x6` = สตริปพาสเทลแนวตั้ง, `grid4x6` = ตาราง 2x2 ธีมมืด + หัวเรืองแสง |

| `DCC_AUTO_START` | `true` | เปิด digiCamControl อัตโนมัติเมื่อมีการตรวจหรือสั่งกล้อง |

## ความเป็นส่วนตัวของลูกค้า

QR แต่ละเซสชัน**เป็นลิงก์แยกของตัวเอง** สร้างขึ้นตอนจบเซสชันผ่าน Nextcloud OCS API (root ของ share อยู่ที่โฟลเดอร์เซสชันเลย อ่านอย่างเดียว) ลูกค้ากด "ขึ้นบน" ไม่ได้ เพราะไม่มีโฟลเดอร์แม่ให้ขึ้น — เห็นเฉพาะไฟล์ของตัวเอง เห็นเซสชันคนอื่นไม่ได้เด็ดขาด

ต้องตั้งค่า 3 ตัวใน `.env` ถึงจะใช้ได้ (ตั้งไว้ให้แล้วในเครื่องนี้):

| ตัวแปร | ความหมาย |
|---|---|
| `NC_USER` | บัญชี Nextcloud ที่เป็นเจ้าของโฟลเดอร์ `photobooth` |
| `NC_APP_PASSWORD` | สร้างจาก Nextcloud → รูปโปรไฟล์ → การตั้งค่าส่วนบุคคล → ความปลอดภัย → Devices & sessions → Create new app password |
| `NC_OWNER_PREFIX` | โฟลเดอร์ที่ `photobooth` อยู่ข้างใน นับจาก Files ของบัญชีนั้น (เครื่องนี้คือ `photo boot`) |

จอช่างมีแถบ **"ลิงก์แยกต่อเซสชัน"** เช็คสถานะได้ — ถ้าขึ้นแดง ห้ามใช้งานจริงเด็ดขาด (ระบบจะโยน error ทันทีตอนจบเซสชัน ไม่มี fallback แบบไม่ปลอดภัยให้ใช้แทน)

## แก้ปัญหา

| อาการ | สาเหตุที่พบบ่อย |
|---|---|
| จอช่างขึ้น "ไม่เห็นกล้อง" | digiCamControl ไม่ได้เปิด / สาย USB หลุด / กล้องปิด / Capture One แย่ง tether อยู่ |
| ไม่มี live view | webserver ของ digiCamControl เปิดไม่ได้ (ดูหัวข้อ urlacl ด้านบน) — แอปตกไปใช้ named pipe อัตโนมัติ |
| `หมดเวลารอไฟล์จากกล้อง` | โฟกัสไม่เข้าเลยไม่ลั่นชัตเตอร์ (ตั้ง MF หรือปิด focus before capture) / การ์ดเต็ม |
| อัปโหลดค้าง | เน็ตหลุด — retry 3 ครั้งต่อไฟล์ ไฟล์ยังอยู่ใน `sessions/` และ `CAPTURE_DIR` |
