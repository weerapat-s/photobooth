# Photo Booth DSLR + iPad Web (EOS R → Windows bridge → iPad → Nextcloud/Print)

ระบบโฟโต้บูทแบบบริการตัวเองตามโครงสร้าง DSLR booth: Canon EOS R ติดเหนือจอและต่อ USB เข้ากล่อง Windows/mini PC ที่ซ่อนในบูท ส่วน iPad เปิดหน้าเว็บเป็นจอสัมผัสผ่าน Wi-Fi

- **iPad (booth)** — เปิดหน้าเว็บ Photo Booth ลูกค้ากดเริ่ม ตรวจรูป และถ่ายใหม่เฉพาะช่องเอง
- **Windows bridge** — ควบคุม EOS R ผ่าน digiCamControl และส่งสถานะ/ภาพกลับหน้าเว็บ
  จากนั้น backend จัดหน้าสตริป ทำวิดีโอ อัปโหลดขึ้น Nextcloud แล้วโชว์ QR
- **backend/bridge** — รันบน Windows ที่ต่อสาย USB กับ EOS R โดยตรง; ไม่จำเป็นต้องมี Mac หรือแอป iPad แบบ native
- **เครื่องปริ้น (print booth)** — ดึงคิวงานจาก Nextcloud โฟลเดอร์เดียวกัน แล้วสั่งพิมพ์ ตั้งกี่เครื่องก็ได้ อยู่คนละสถานที่ก็ได้

ทั้งหมดคุยกันผ่าน Nextcloud share `https://nextcloud.ienas.site/s/<SHARE_TOKEN>` เท่านั้น ไม่ต้องอยู่วง LAN เดียวกัน — เครื่องปริ้นจะอยู่คนละตึก คนละจังหวัดก็ได้ ขอแค่มีเน็ต

## แหล่งภาพ 5 โหมด (เลือก `digicam` สำหรับ DSLR booth)

| `CAPTURE_SOURCE` | ใครลั่นชัตเตอร์ | live view | ใช้เมื่อ |
|---|---|---|---|
| `digicam` (เลือกใช้) | ลูกค้ากดบนเว็บ iPad แล้ว Windows สั่งกล้อง | เฉพาะ DCC webserver | EOS R ต่อ USB เข้ากล่อง Windows ที่ซ่อนในบูท |
| `folder` | เจ้าหน้าที่กดกล้อง / รีโมท | ไม่มี | ใช้ Capture One tether แล้วให้แอปวางภาพลงช่องว่าง |
| `mock` | เจ้าหน้าที่กดปุ่มถ่ายบนจอช่าง | ไม่มี | เทสต์ทั้ง pipeline โดยไม่ต้องมีกล้อง |
| `web` | ลูกค้ากดบน PWA | กล้องใน iPad | ทางเลือกสำรอง ไม่สามารถควบคุม EOS R ผ่าน USB |
| `ipad` | แอป Native iPad สั่ง EOS R ผ่าน USB | อยู่ในแอป | ทางเลือกทดลอง ต้องมี CascableCore license และ Apple signing |

## ตั้งค่าแบบ DSLR booth + เว็บบน iPad

ตั้งค่า `.env` บน backend:

```env
HOST=0.0.0.0
CAPTURE_SOURCE=digicam
KIOSK_MODE=self_service
```

จากนั้น:

1. ต่อ EOS R ผ่านสาย USB data เข้ากล่อง Windows/mini PC แล้วเปิด digiCamControl ให้เห็นกล้อง
2. รัน backend บน Windows และให้ iPad ต่อ Wi-Fi วงเดียวกัน
3. เปิด `http://<IP-Windows>:4700` ด้วย Safari บน iPad
4. เพิ่มหน้าเว็บไว้บน Home Screen แล้วเปิด Guided Access ตามหัวข้อถัดไป เพื่อกันลูกค้าปัดออก
5. เครื่องพิมพ์วางในกล่องแยกและรับคิวผ่าน Nextcloud ตามระบบเดิม

สาย EOS R ไม่ได้ต่อเข้า iPad โดยตรง เว็บเป็นรีโมต UI ส่วน Windows bridge เป็นผู้ควบคุม USB/PTP ของกล้อง จึงไม่ต้องใช้ CascableCore หรือ Apple Developer

เมื่อติดตั้ง shortcut ด้วย `npm run install-shortcuts` แล้ว Windows bridge จะเปิดเองหลังล็อกอินโดยไม่แสดงหน้าต่าง และจะเปิด digiCamControl ให้อัตโนมัติเมื่อหน้าเว็บตรวจกล้อง หน้า iPad ตรวจสถานะทุก 5 วินาที: ถ้าไม่พบ EOS R ปุ่มเริ่มจะถูกล็อก และจะปลดเองเมื่อกล้องพร้อม

ลิงก์ใช้งานจริงผ่าน HTTPS คือ **https://booth.ienas.site** เชื่อมด้วย Cloudflare Tunnel ชื่อ `photobooth-windows-local` และเปิดอัตโนมัติพร้อม Windows bridge โดยไม่ต้อง forward port เราเตอร์ หน้าเว็บโหมดบริการตัวเองต้องจับคู่ด้วย `WEB_PAIR_CODE` หนึ่งครั้งก่อนใช้งาน คุกกี้จับคู่เป็น HttpOnly/SameSite ส่วน `IPAD_API_TOKEN` แบบยาวยังเป็น master secret ของ API และ API แบบเดิมถูกปิดในโหมดนี้ไม่ให้คนภายนอกสั่งกล้องโดยไม่ยืนยัน

Scheduled Task **Photo Booth Bridge Watchdog** ตรวจทุก 1 นาที หาก backend หรือ Cloudflare Tunnel หยุดจะเปิดกลับอัตโนมัติ เพื่อลดโอกาสเกิด Cloudflare Error 1033 หลังโปรเซสถูกปิดหรือเครื่องกลับจาก sleep

### ล็อก iPad ไม่ให้ลูกค้าปัดออกจาก Photo Booth

เว็บไซต์บล็อกท่าทางระบบของ iPadOS เองไม่ได้ จึงใช้ **Guided Access** ของ iPad ซึ่งล็อกเครื่องให้อยู่ในเว็บแอปเดียวและต้องใช้รหัสเจ้าหน้าที่จึงจะออกได้:

1. iPad: **การตั้งค่า → การช่วยการเข้าถึง → การใช้งานเครื่องตามที่กำหนด (Guided Access)** แล้วเปิดใช้งาน
2. เข้า **การตั้งค่ารหัส → ตั้งรหัส Guided Access** และตั้งรหัสที่ลูกค้าไม่รู้ ปิด Touch ID สำหรับการออกถ้าไม่ต้องการให้ใครใช้นิ้วปลด
3. เปิด Photo Booth จากไอคอนบนหน้าจอโฮม ไม่ใช่แท็บ Safari
4. กดปุ่มด้านบนของ iPad 3 ครั้ง เลือก Guided Access แล้วกด **เริ่ม**
5. ทดสอบปัดขึ้น/สลับแอป: ต้องออกไม่ได้ หากเจ้าหน้าที่จะออก ให้กดปุ่มด้านบน 3 ครั้งและใส่รหัส Guided Access

อย่าปิดตัวเลือก **การสัมผัส** ในการตั้งค่าเซสชัน เพราะลูกค้ายังต้องกดปุ่มถ่ายบนจอ

## ตั้ง digiCamControl

1. ต่อกล้อง DSLR ผ่าน USB เปิดกล้อง ตั้งเป็นโหมด PC connection แล้วเปิด **digiCamControl** ให้เห็นกล้อง
2. **ปิด Capture One** ระหว่างใช้โหมด `digicam` — สองโปรแกรมจับกล้องพร้อมกันไม่ได้
3. ให้ digiCamControl เปิดค้างไว้ตลอดงาน (แอปคุยกับมัน ไม่ได้คุยกับกล้องตรง ๆ)

### live view ต้องใช้ webserver ของ digiCamControl

`UseWebserver` ถูกเปิดไว้ให้แล้วใน `C:\ProgramData\digiCamControl\settings.json` (สำรองไว้ที่ `settings.json.bak`)
แต่ digiCamControl bind พอร์ต 5513 ไม่ได้ถ้าไม่มีสิทธิ์ — log จะขึ้น `Unable to start webserver`

แก้ครั้งเดียวจบ เปิด **PowerShell แบบ Run as Administrator** แล้วรัน (ใส่ชื่อบัญชีเต็ม `คอม\ผู้ใช้` — `%USERNAME%` ไม่ขยายใน PowerShell จะได้ error 1332):

```bash
netsh http add urlacl url=http://+:5513/ user="เครื่องนี้\ชื่อผู้ใช้"
```

ตรวจว่าได้ผล: `netsh http show urlacl url=http://+:5513/` แล้วปิดเปิด digiCamControl ใหม่

(หรือจะเปิด digiCamControl แบบ Run as Administrator ทุกครั้งก็ได้ ไม่ต้องแก้ urlacl)

ถ้ายังเปิด webserver ไม่ได้ แอปจะ **ตกไปใช้ named pipe (`CameraControlRemoteCmd.exe`) ให้อัตโนมัติ** — ถ่ายได้ปกติ แค่ไม่มี live view บนจอลูกค้า

## เซสชันเริ่ม/จบยังไง

**โหมด `KIOSK_MODE=self_service`:** ลูกค้ากดเริ่มบน iPad → ระบบนับถอยหลังและสั่ง EOS R ผ่าน Windows → ตรวจภาพแต่ละช่อง → ถ้าไม่ชอบกดถ่ายใหม่เฉพาะช่องนั้น รูปช่องอื่นไม่เลื่อน → เมื่อครบกดยืนยัน → จัดหน้า + ทำวิดีโอ + อัปโหลด + โชว์ QR

**โหมดเจ้าหน้าที่:** เจ้าหน้าที่กด "เริ่มเซสชันใหม่" บนจอช่าง → กดถ่ายทีละช่อง → ตรวจภาพแต่ละช่อง → ถ้าภาพเสียให้กด "ลบรูป" หรือ "ถ่ายใหม่" ที่ช่องนั้น รูปช่องอื่นจะไม่เลื่อน → เมื่อครบทุกช่องกด "ยืนยันรูปทั้งหมด + จบงาน"

**โหมด folder:** เจ้าหน้าที่กดเริ่มเซสชันก่อน แล้วกดชัตเตอร์เอง ไฟล์ JPEG จะลงช่องว่างถัดไป ต้องตรวจและกดยืนยันจบงานเองเหมือนกัน (ไฟล์ RAW ถูกข้าม)

## เลขคิวปริ้น (hand-off ไปเครื่องปริ้นที่อยู่คนละที่)

กดปริ้น (หรือ `PRINT_ON_DONE=true` ให้ส่งอัตโนมัติ) ระบบจะจอง **เลขคิว** ให้ 1 เลขต่อ 1 เซสชัน (รีเซ็ตทุกวัน) แล้วโชว์บนจอลูกค้า ("คิวปริ้น #12") และจอช่าง — ใช้เลขนี้บอกลูกค้าแทนการเดินไปดูหน้าจอที่เครื่องปริ้น

การจองเลขใช้ WebDAV MKCOL ซึ่ง Nextcloud การันตีสร้างชื่อซ้ำไม่ได้ ต่อให้มีเครื่องถ่ายหลายเครื่องส่งงานพร้อมกันก็ไม่มีทางได้เลขชนกัน

**จอบอร์ดคิว** (`/queue.html` บนเครื่องปริ้น) โชว์เลขคิวที่กำลังพิมพ์ตัวใหญ่เต็มจอ อัปเดตอัตโนมัติทุก 3 วิ เอาไปเปิดบนทีวี/มอนิเตอร์ตรงจุดรับรูปได้เลย ไม่ต้องอยู่เครื่องเดียวกับที่พิมพ์จริง (เปิดจากเครื่องไหนก็ได้ที่เข้า `http://<ip เครื่องปริ้น>:4702/queue.html` ได้)

## โครงสร้างไฟล์บน Nextcloud

```
photobooth/
  <booth>-<YYYYMMDD-HHmmss>/     # 1 เซสชัน = 1 โฟลเดอร์ (QR ชี้มาที่นี่)
    photo-1..N.jpg               # ไฟล์จากกล้อง
    card.jpg                     # การ์ด/สตริปที่จัดหน้าแล้ว
    print.jpg                    # สำเนาเดียวกับ card.jpg เอาไว้ส่งเข้าคิวปริ้น (strip2x6 = 2x6 นิ้ว, grid4x6 = 4x6 นิ้วพอร์เทรต)
    video.mp4 / video.gif        # วิดีโอบูมเมอแรงจากช็อตที่ถ่าย
  _print/queue/Q<เลขคิว>__<session>__<เวลา>.json   # งานรอพิมพ์
  _print/claimed/                # เครื่องปริ้นเครื่องไหนกำลังทำอยู่
  _print/done/                   # พิมพ์แล้ว
  _print/failed/                 # พิมพ์ไม่สำเร็จ
  _print/tickets/<YYYYMMDD>/     # ตัวจองเลขคิว — โฟลเดอร์ว่างเปล่า ใช้แค่กันชนกัน รีเซ็ตทุกวัน
```

## ติดตั้ง

```bash
npm install
```

คัดลอก `.env.example` เป็น `.env` แล้วแก้ค่า (ไฟล์ `.env` ที่ให้มาตั้งไว้ตรงกับเครื่องนี้แล้ว)

## เปิดแบบแอพ (ไอคอนบนเดสก์ท็อป)

```bash
npm run install-shortcuts
```

ได้ไอคอน **Photo Booth** (จอลูกค้า เต็มจอ), **จอช่าง**, **บูทปริ้น** ทั้งบนเดสก์ท็อปและใน Start Menu

ดับเบิลคลิกแล้วจะเปิดเซิร์ฟเวอร์แบบซ่อนหน้าต่าง รอจนพร้อม แล้วเปิดหน้าจอในเบราว์เซอร์แบบ app window
ปิดหน้าต่างสุดท้ายที่ใช้พอร์ตนั้น = ปิดเซิร์ฟเวอร์ให้เอง (จอลูกค้ากับจอช่างใช้เซิร์ฟเวอร์ตัวเดียวกัน)

ออกจากโหมดเต็มจอ: `Alt+F4`
log อยู่ที่ `logs/booth.log`, `logs/print.log` — ลบไอคอน: `npm run uninstall-shortcuts`

**จอลูกค้าอยู่คนละจอกับจอช่าง:** ตั้ง `BOOTH_MONITOR=2` แล้วเปิดไอคอน Photo Booth ระบบย้ายเต็มจอให้อัตโนมัติ

## รันจากเทอร์มินัล

npm start

รันเครื่องปริ้นบนเครื่องนี้เอง (ทดสอบ/setup เล็ก ๆ ที่ถ่ายกับปริ้นอยู่เครื่องเดียวกัน — ถ้าจะแยกเครื่องจริงดูหัวข้อ "เครื่องปริ้น" ด้านล่าง):

## เครื่องปริ้น (แพ็กเกจแยก ติดตั้งได้หลายเครื่อง คนละสถานที่)

`photobooth/printbooth/` เป็น **แพ็กเกจของตัวเอง** (`package.json`/`.env`/dependency แยกจากเครื่องถ่ายทั้งหมด) คุยกับเครื่องถ่ายผ่าน Nextcloud อย่างเดียว ก๊อปไปวางเครื่องไหนก็ได้ กี่เครื่องก็ได้ ไม่ต้องอยู่ LAN เดียวกัน

**ติดตั้งเครื่องปริ้นเครื่องใหม่:**

```bash
npm run pack-printbooth
```

รันจากเครื่องนี้ (เครื่องหลัก) — ได้โฟลเดอร์ `dist/printbooth/` ที่ไม่มีรหัส Nextcloud ฝังอยู่ ก๊อปทั้งโฟลเดอร์ไปวางบนเครื่องปริ้น แล้วดับเบิลคลิก `install.cmd` จากนั้นกรอกค่าประจำเครื่องและ Nextcloud ใน `.env`:

```
PRINTER_ID=print-2          # ห้ามซ้ำกับเครื่องปริ้นเครื่องอื่น
PRINTER_NAME=ชื่อเครื่องพิมพ์  # ดูจาก Settings > Printers & scanners
NC_SHARE_TOKEN=...          # token ของ share หลัก
NC_SHARE_PASSWORD=...       # เว้นว่างถ้า share ไม่มีรหัส
```

ได้ไอคอน **"บูทปริ้น"** (คอนโซลช่าง) กับ **"คิวปริ้น"** (จอบอร์ดเต็มจอ) บนเดสก์ท็อป

**หลายเครื่องพิมพ์งานเดียวกันไม่ซ้ำกันยังไง:** งานหนึ่งชิ้นถูก "จอง" ด้วยการย้ายไฟล์ (WebDAV MOVE เป็น atomic) เครื่องแรกที่ย้ายสำเร็จได้งานไป เครื่องอื่นข้าม ถ้าเครื่องที่จองดับกลางคัน งานที่ค้างเกิน `STALE_CLAIM_MINUTES` นาทีจะถูกเอากลับเข้าคิวให้เครื่องอื่นทำต่ออัตโนมัติ

| ตัวแปร | ความหมาย |
|---|---|
| `PRINTER_ID` | ต้องไม่ซ้ำกับเครื่องอื่น (เว้นว่าง = ใช้ชื่อคอมพิวเตอร์) |
| `PRINTER_NAME` | ชื่อเครื่องพิมพ์ (เว้นว่าง = ค่าเริ่มต้นของ Windows) |
| `PAPER` | `4x6` `6x4` `2x6` `5x7` — ต้องตรงกับ `PRINT_LAYOUT` จริง: `strip2x6` ตั้ง `PAPER=2x6`, `grid4x6` ตั้ง `PAPER=4x6` (ถ้าไดรเวอร์ไม่มีขนาดนี้จะใช้ค่าเริ่มต้นของไดรเวอร์) |
| `AUTO_PRINT` | `true` = เจอคิวแล้วพิมพ์เลย, `false` = โชว์คิวเฉย ๆ |
| `POLL_SECONDS` | ความถี่ในการดึงคิว |
| `DRY_RUN` | `true` = ไม่พิมพ์จริง แค่บอกว่าจะพิมพ์อะไร |
| `MAX_COPIES` | จำกัดจำนวนสำเนาสูงสุดต่องาน |
| `ACCEPT_BOOTHS` | เว้นว่าง = รับทุกบูท หรือระบุ เช่น `booth-1,booth-2` ให้เครื่องนี้รับเฉพาะบูทที่ระบุ |
| `STALE_CLAIM_MINUTES` | งานที่จองค้างเกินนี้ (เครื่องดับ) เอากลับเข้าคิว |

ทดสอบเครื่องพิมพ์แบบไม่เปลืองกระดาษ:

```bash
powershell -ExecutionPolicy Bypass -File printbooth/print.ps1 -ImagePath "C:\path\print.jpg" -Paper 4x6 -PrinterName "Canon iX6700 series XPS" -DryRun
```

รันจากเทอร์มินัลตรง ๆ (ไม่ผ่านไอคอน): `cd printbooth && npm start`

## ความเป็นส่วนตัวของลูกค้า

QR แต่ละเซสชัน**เป็นลิงก์แยกของตัวเอง** สร้างขึ้นตอนจบเซสชันผ่าน Nextcloud OCS API (root ของ share อยู่ที่โฟลเดอร์เซสชันเลย อ่านอย่างเดียว) ลูกค้ากด "ขึ้นบน" ไม่ได้ เพราะไม่มีโฟลเดอร์แม่ให้ขึ้น — เห็นเฉพาะไฟล์ของตัวเอง เห็นเซสชันคนอื่นไม่ได้เด็ดขาด

ต้องตั้งค่า 3 ตัวใน `.env` ถึงจะใช้ได้ (ตั้งไว้ให้แล้วในเครื่องนี้):

| ตัวแปร | ความหมาย |
|---|---|
| `NC_USER` | บัญชี Nextcloud ที่เป็นเจ้าของโฟลเดอร์ `photobooth` |
| `NC_APP_PASSWORD` | สร้างจาก Nextcloud → รูปโปรไฟล์ → การตั้งค่าส่วนบุคคล → ความปลอดภัย → Devices & sessions → Create new app password |
| `NC_OWNER_PREFIX` | โฟลเดอร์ที่ `photobooth` อยู่ข้างใน นับจาก Files ของบัญชีนั้น (เครื่องนี้คือ `photo boot`) |

จอช่างมีแถบ **"ลิงก์แยกต่อเซสชัน"** เช็คสถานะได้ — ถ้าขึ้นแดง ห้ามใช้งานจริงเด็ดขาด (ระบบจะโยน error ทันทีตอนจบเซสชัน ไม่มี fallback แบบไม่ปลอดภัยให้ใช้แทน)

## แก้ปัญหา

| อาการ | สาเหตุที่พบบ่อย |
|---|---|
| จอช่างขึ้น "ไม่เห็นกล้อง" | digiCamControl ไม่ได้เปิด / สาย USB หลุด / กล้องปิด / Capture One แย่ง tether อยู่ |
| ไม่มี live view | webserver ของ digiCamControl เปิดไม่ได้ (ดูหัวข้อ urlacl ด้านบน) — แอปตกไปใช้ named pipe อัตโนมัติ |
| `หมดเวลารอไฟล์จากกล้อง` | โฟกัสไม่เข้าเลยไม่ลั่นชัตเตอร์ (ตั้ง MF หรือปิด focus before capture) / การ์ดเต็ม |
| อัปโหลดค้าง | เน็ตหลุด — retry 3 ครั้งต่อไฟล์ ไฟล์ยังอยู่ใน `sessions/` และ `CAPTURE_DIR` |
| ปริ้นไม่ออก | เช็ค `http://localhost:4701` ดู `_print/failed/` หรือ `_print/review/` แล้วลอง `-DryRun` |
